QEMU 에뮬레이션 rv64(vlen=256, RVV 1.0)

  • onnxruntime 부분 동작 build_riscv64.sh가 qemu로 크로스 컴파일 산출물을 검증하는 구조입니다. 돌긴 하지만 매우 느립니다. raw.githubusercontent.com
  • pytorch 부분 동작 RISE 휠이 “QEMU 빌드 아님”이라고 명시하고 있어 qemu에서는 기능 검증만 가능합니다. riseproject.dev
  • opencv 동작 에뮬레이션 환경에서 동작하며 성능 의미는 없습니다. github.com
  • ncnn 동작 CI가 riscv64에서 통과합니다. github.com

SiFive HiFive Unmatched

SiFive FU740(4x U74, RV64GC, V 없음)
  • llama.cpp 공개 자료 없음 Unmatched 전용 공개 실측을 찾지 못했습니다. 업스트림은 소스만 제공(release에 riscv64 바이너리 없음)하고 U74에는 RVV가 없어 스칼라 경로뿐이라 매우 느릴 것으로 보입니다. github.comgithub.com
  • onnxruntime 부분 동작 업스트림에 MLAS RVV kernel과 tools/scripts/build_riscv64.sh(SiFive 기여)가 있지만 riscv64 사전 빌드 패키지가 없어 직접 크로스 컴파일해야 합니다. RVV kernel은 RVV 1.0 대상입니다. raw.githubusercontent.comgithub.com
  • pytorch 부분 동작 PyPI에는 riscv64 휠이 없습니다. RISE가 torch 2.13.0 manylinux_2_39_riscv64 휠을 제공합니다(glibc ≥ 2.39 필요, 예: Ubuntu 24.04/Bianbu). riseproject.devpypi.riseproject.dev
  • opencv 동작 업스트림 4.x가 RISC-V와 RVV HAL을 지원합니다. 대부분 배포판에서 설치하거나 RVV 백엔드로 직접 빌드할 수 있습니다. 보드별 성능 검증은 하지 않았습니다. github.com
  • ncnn 부분 동작 업스트림에 linux-riscv64 CI와 RVV 구현이 있지만 U74에는 RVV가 없어 ncnn은 스칼라로만 돕니다. github.comgithub.com
  • tengine 부분 동작 tengine-lite가 risc-v/lp64dv용 RVV 컨볼루션 kernel과 rv64-c906 툴체인을 제공하며 일부 연산자만 최적화된 실험적 지원입니다. raw.githubusercontent.comgithub.com

LicheePi 4A(리치파이 4A)

T-HEAD TH1520 (4x C910 @1.85GHz, RV64GCV 0.7.1)
  • llama.cpp 동작 Sipeed 공식 wiki에 llama.cpp 장이 있습니다. 7B 모델에서 약 6s/token(V 확장 미사용). C910은 RVV 0.7.1이라 업스트림 RVV 1.0 최적화 경로를 쓸 수 없어 스칼라로만 돕니다. raw.githubusercontent.comgithub.com
  • onnxruntime 부분 동작 업스트림 riscv64 빌드의 MLAS RVV kernel은 RVV 1.0 대상이라 TH1520의 0.7.1 벡터를 바로 쓸 수 없어 스칼라로 되돌아갑니다. raw.githubusercontent.com
  • pytorch 부분 동작 RISE 휠은 glibc ≥ 2.39에 RVV 1.0 최적화 경로입니다. RevyOS/Debian에서 설치되지만 벡터 가속은 없습니다. riseproject.dev
  • opencv 동작 일반적으로 사용 가능합니다. RVV HAL은 0.7.1 지원이 제한적입니다. github.com
  • ncnn 부분 동작 컴파일은 되지만 RVV 최적화는 1.0 대상이라 0.7.1에서는 스칼라로 퇴화합니다. github.com
  • tengine 부분 동작 tengine-lite에 rv64-c906 툴체인과 RVV 컨볼루션 kernel이 있어 C906/C910 같은 0.7.1 코어를 겨냥하지만 일부 연산자만 커버합니다. github.com
  • npu-sdk (HHB) 부분 동작 공식 wiki의 NPU 절차는 T-Head HHB 컴파일러로 ONNX를 NPU 실행 파일(int8/int16 고정소수점)로 바꾸는 것이고 전용 docker 이미지가 필요합니다. 클로즈드 툴체인이고 고정소수점만 지원해 LLM에는 맞지 않습니다. raw.githubusercontent.com

NPU / 가속기4 TOPS@INT8, 벤더 클로즈드 HHB 툴체인(int8/int16 고정소수점)뿐이고 업스트림 오픈소스 드라이버가 없습니다

SpacemiT K3(Pico-ITX / CoM260)

SpacemiT K3(A100 코어, RV64GCV + RVV 1.0)

  • spacemit-llama.cpp (벤더) 동작 SpacemiT가 spacemit-llama.cpp.riscv64 사전 빌드를 제공하고(0.0.9까지 나옴) archive.spacemit.com 모델 라이브러리와 함께 씁니다. Bit-Brick 문서에 llama-cli/llama-server 사용법이 있습니다. archive.spacemit.comdocs.bit-brick.com

  • tengine 부분 동작 사용할 수 있지만 최적화가 0.7.1 C906 대상이라 1.0에서는 이득이 제한적입니다. github.com
  • spacemit-ai-sdk 동작 archive.spacemit.com/spacemit-ai/가 ModelZoo, llama.cpp, localai, dify 같은 산출물을 제공하며 현재 RISC-V에서 가장 완성도 높은 벤더 AI 스택 중 하나입니다. archive.spacemit.com
