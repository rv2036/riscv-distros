LicheePi 4A

T-HEAD TH1520 (4x C910 @1.85GHz, RV64GCV 0.7.1)
  • llama.cpp Works Sipeed's official wiki has a llama.cpp section: about 6s/token for a 7B model (without the V extension). C910 is RVV 0.7.1, so upstream's RVV 1.0 optimisation path does not apply and it stays scalar. raw.githubusercontent.comgithub.com
  • onnxruntime Partial Upstream's riscv64 MLAS RVV kernel targets RVV 1.0; the TH1520's 0.7.1 vectors can't use it, so it falls back to scalar. raw.githubusercontent.com
  • pytorch Partial RISE wheels need glibc >= 2.39 and are optimised for RVV 1.0; they install on RevyOS/Debian but give no vector acceleration. riseproject.dev
  • opencv Works Works as usual; the RVV HAL has limited 0.7.1 support. github.com
  • ncnn Partial Builds, but the RVV optimisations target 1.0 and degrade to scalar on 0.7.1. github.com
  • tengine Partial tengine-lite ships an rv64-c906 toolchain and RVV convolution kernels built for 0.7.1 cores like the C906/C910, but only some operators are covered. github.com
  • npu-sdk (HHB) Partial The official wiki documents the NPU flow: the T-Head HHB compiler turns ONNX into NPU executables (int8/int16 fixed point) inside a dedicated Docker image; the toolchain is closed source and fixed-point only, so it is unsuitable for LLMs. raw.githubusercontent.com

NPU / accelerator4 TOPS@INT8, vendor closed-source HHB toolchain only (int8/int16 fixed point), no upstream open-source driver

Running an LLM on the CPU works but is slow (~6s/token); the NPU only has the closed T-Head HHB path and cannot run Transformer LLMs.
