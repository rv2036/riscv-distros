Bottom line

Aimed at industrial/production use; hobbyists should start with Armbian or Buildroot instead.

Based on
Built from source (BitBake + oe-core + meta-riscv)
Upstream
Build system: oe-core ships the qemuriscv32/qemuriscv64 machines and a riscv64 tune; concrete boards come from the official RISC-V layer meta-riscv (under the riscv/ org), which provides the machine configs.

Boards

  • QEMU virt (virtual machine) Official Native qemuriscv64/qemuriscv32 in oe-core
  • Banana Pi BPI-F3 (SpacemiT K1) Community meta-riscv's bananapi-f3 (mainline kernel/U-Boot, still needs the vendor FSBL)
  • SpacemiT K3 (Pico-ITX / CoM260) Community meta-riscv's k3-com260 / k3-pico-itx (including -mainline variants)
  • LicheePi 4A Community meta-riscv's licheepi-4a
  • StarFive VisionFive 2 Community meta-riscv's visionfive2
  • Orange Pi RV2 (Ky X1) Community meta-riscv's orangepi-rv2 (mainline kernel/U-Boot + vendor FSBL)
  • Zhihe A210 (XuanTie MelonPi dev board) Community meta-riscv's zhihe-a210: OSU-OSL mainline kernel, TFTP netboot only, no bootloader recipe

Pitfalls

  • Steepest learning curve: BitBake syntax plus layer versions that must match exactly (meta-riscv tracks master)
  • The first build downloads tens of GB and takes hours
  • No ready-made images; you produce the wic/sdimg yourself
  • The vendor FSBL/TEE still has to be obtained separately — a purely open-source flow won't work
