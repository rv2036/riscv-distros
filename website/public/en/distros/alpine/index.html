Bottom line

Alpine's riscv64 is a real architecture, but board coverage is narrow — there are only those five u-boot packages, so anything outside them means porting it yourself.

Boards

  • QEMU virt (virtual machine) Official An official u-boot-qemu package exists; QEMU is the standard development path
  • SiFive HiFive Unmatched Official Official u-boot-unmatched / u-boot-unleashed packages exist
  • StarFive VisionFive 2 Official An official u-boot-starfive package exists (StarFive JH7110 family)
  • LicheePi 4A Partial No official u-boot-th1520-style package; bring your own bootloader
  • Milk-V Meles Partial TH1520 platform, as above
  • SpacemiT K3 (Pico-ITX / CoM260) Community An official u-boot-spacemit package exists (SpacemiT platforms, mainly K1); whether K3 is covered separately is unconfirmed
  • Zhihe A210 (XuanTie MelonPi dev board) Partial No official u-boot package
  • Canaan K230 (Kendryte K230 / CanMV-K230) Partial No official u-boot package
  • Milk-V Megrez (ESWIN EIC7700X) Partial No official u-boot package
  • Milk-V Titan (UltraRISC DP1000) Partial No official u-boot package
  • Milk-V Pioneer (SG2042, server-oriented) Partial No official u-boot package
  • Orange Pi RV2 (Ky X1) Partial SpacemiT K1 board, possibly reusing u-boot-spacemit; unconfirmed
  • Banana Pi BPI-F3 (SpacemiT K1) Partial SpacemiT K1 board, possibly reusing u-boot-spacemit; unconfirmed

Pitfalls

  • Official u-boot only covers qemu / starfive / spacemit / unleashed / unmatched; other boards need your own bootloader
  • musl libc + busybox: prebuilt binaries that need glibc won't run
  • The official wiki (wiki.alpinelinux.org) returns 403 to automated requests, so RISC-V details can only be inferred from the packages/downloads pages
