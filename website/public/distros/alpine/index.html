先说结论

Alpine 的 riscv64 是正式架构，但板级支持面窄——u-boot 包就那五个，超出范围的板子等于自己移植。

支持的开发板

  • QEMU virt 虚拟机型 官方支持 官方提供 u-boot-qemu 包，QEMU 为标准开发路径
  • SiFive HiFive Unmatched 官方支持 官方提供 u-boot-unmatched / u-boot-unleashed 包
  • StarFive VisionFive 2 官方支持 官方提供 u-boot-starfive 包（StarFive JH7110 系）
  • 荔枝派 4A（LicheePi 4A） 部分可用 无 u-boot-th1520 类官方包，需自备引导
  • Milk-V Meles 部分可用 TH1520 平台，同上
  • 进迭时空 SpacemiT K3（Pico-ITX / CoM260） 社区可用 官方有 u-boot-spacemit 包（SpacemiT 平台，以 K1 系为主）；K3 是否单独覆盖未确认
  • 知合计算 A210（玄铁 MelonPi 开发板） 部分可用 无官方 u-boot 包
  • 嘉楠 Canaan K230（Kendryte K230 / CanMV-K230） 部分可用 无官方 u-boot 包
  • Milk-V Megrez（ESWIN EIC7700X） 部分可用 无官方 u-boot 包
  • Milk-V Titan（UltraRISC DP1000） 部分可用 无官方 u-boot 包
  • Milk-V Pioneer（SG2042 服务器向） 部分可用 无官方 u-boot 包
  • Orange Pi RV2（Ky X1） 部分可用 SpacemiT K1 板，可能复用 u-boot-spacemit，未确认
  • Banana Pi BPI-F3（SpacemiT K1） 部分可用 SpacemiT K1 板，可能复用 u-boot-spacemit，未确认

坑

  • 官方 u-boot 只覆盖 qemu / starfive / spacemit / unleashed / unmatched 五类，其余板子要自己准备引导
  • musl libc + busybox：依赖 glibc 的预编译二进制跑不了
  • 官方 wiki (wiki.alpinelinux.org) 对自动化访问返回 403，RISC-V 细节只能从 packages/downloads 页反推
