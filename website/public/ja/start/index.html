まず、何をしたいのかを決める

典型的な目的は 3 つで、ルートがまったく違います。

  • RISC-V がどんなものか眺めたいだけ：QEMU をそのまま使えば 10 分でシステムに入れます。ボードを買う必要はありません。
  • 実機で、規模の大きくない開発をしたい：ソフトウェアスタックが成熟していて、公式イメージで起動できるボードを買ってください（このページの下に一覧があります）。
  • AI 推論や特定チップの検証をしたい：AI ソフト のページで動いた実績があるか先に確認してから、何を買うか決めてください。

ステップ 1：QEMU（全員ここから）

QEMU は既定の RISC-V エミュレータで、ほぼすべてのディストロが最初に対応します。良い点は届くのを待たなくてよく、壊れたら入れ直せば済むこと。悪い点は性能が実機の参考にならず、ドライバの問題も見つからないことです。ディストロのページで QEMU 対応があるものは「公式対応」と書いています。

ステップ 2：ボードを選ぶ

判断の基準は 3 つだけで、順番に見ていきます。

  1. 公式イメージがあるか：ベンダー自身が配布するイメージだけが「挿せばそのまま点灯する」ものです。コミュニティ移植は U-Boot を自分でビルドすることになりがちです。
  2. カーネルが上流にあるか：カーネルがメインラインに入って初めて、ディストロが直接インストールできるようになります。ベンダーの 5.10/6.1 ブランチだけに頼るボードは、アップグレードでほぼ確実に壊れます。
  3. 使っている人がいるか：フォーラム、チャット、GitHub issue の活発さが、詰まったときに答えが見つかるかどうかを決めます。

ステップ 3：イメージを書き終えたら

  • シリアルが最初のデバッグ手段です。ほとんどのボードは、初回起動をシリアルで U-Boot を見ながら行います。
  • すぐにディストロを変えないでください。ベンダーイメージで起動できたらまず動かし、ハードウェアが正常だと確認してから他のシステムを試します。
  • 変える前に、そのディストロのページの「つまずきどころ」を読んでください。多くの問題にはすでに明確な解決策があります。

よくある誤解

  • 「Debian が RISC-V を公式サポート」は「あなたのボードに Debian が入る」と同じではありません：アーキテクチャとしての対応（riscv64）とボード対応（デバイスツリー、U-Boot、ファームウェア）は別の話です。
  • 「カーネルが新しい」は「動く」と同じではありません：ベンダーカーネルの多くは私有ブランチで、デバイスツリーやドライバに手を入れているため、差し替えると起動しません。
  • AI アクセラレータはほぼベンダー SDK 経由です：標準的なフレームワークが RISC-V で動く部分は主に CPU 推論で、NPU は別勘定です。
