結論から

主にベンダー／エコシステムのテスト用です。公式の位置づけが「早期検証」で、ファームウェアやプラットフォームの意味論、カーネルとの相互運用の問題を早く炙り出し、ベンダー側の分岐を減らすことが目的です。一般ユーザーが入れる必要はほとんどなく、日常用途なら Bianbu / RevyOS / openKylin のようなベンダー版を選んでください。まず試したいだけなら QEMU イメージが手軽です。

ベース
独立自前ビルド（RPM ＋ dnf、ローリングリリース）。カーネル 7.2.6 / LTS 6.18.54、ツールチェーンは GCC 16.2 / glibc 同梱
アップストリーム
独立したディストリビューションです。中国科学院ソフトウェア研究所（ISCAS）が立ち上げ、長期にわたって保守している RISC-V ネイティブのディストリビューションで、独自の RPM パッケージ群とビルドパイプライン（SPECS/dnf）を持ちます。Debian/Ubuntu/openEuler のバイナリパッケージをベースにはしていません。

つまずきどころ

  • ローリングリリースで LTS はありません。月次版で大きく変わることがあり、安定した本番基盤には向きません
  • イメージは RVA20 / RVA23 の 2 系統で、対応プロファイルを持たないコアに間違った方を入れると起動しません
  • K3 は Ruyi Firmware（coreboot+OpenSBI+EDK2）と組み合わせる必要があり、一般的な U-Boot ボードの多くには既成イメージがありません
  • インストーラはディスク全体をフォーマットし、既定ではサーバー／ワークステーション向けです。中国語のデスクトップが最初から使えるわけではありません
  • ドキュメントはすべて英語で、中国語の資料はごくわずかです。コミュニティも小規模です
